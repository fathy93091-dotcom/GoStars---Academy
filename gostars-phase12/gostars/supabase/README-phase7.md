# المرحلة 7 — النظام المالي

## القواعد (حسب الدليل)
- **قيمة الحصص المستهلكة** = عدد الحصص الحاضر/المتأخر × سعر الحصة **وقت الحضور** (يُثبَّت السعر على كل حصة؛ الغائب لا يُحتسب).
- **الرصيد = المدفوع − المستهلك.** موجب = رصيد متبقٍّ للطالب، سالب = مديونية. يُحسب تلقائياً في قاعدة البيانات (عرض `student_balances`) دون تدخل يدوي.
- لا مقدم/مؤخر/مختلط.

## ما أُضيف
- **المدير والمشرف (صلاحية «إدارة المالية»):**
  - `/manage/finance`: مجاميع (المستهلك، المدفوع، المديونيات، الأرصدة) + جدول الطلاب مع بحث وفلتر (مدينون / أصحاب رصيد).
  - `/manage/finance/:id`: صفحة مستقلة لكل طالب: الرصيد، تسجيل دفعة (مبلغ، تاريخ، طريقة، بيان)، سعر الحصة، قائمة المدفوعات، الحصص المستهلكة بأسعارها.
  - تبويب «مستحقات المعلمين» لكل شهر.
- **المعلم:** نفس الشاشة داخل ملف **طالبه الشخصي فقط**. طلاب الأكاديمية لا يرى المعلم ماليتهم.
- **المدير فقط:** تصحيح دفعة (لا حذف للمدفوعات أبداً) وتسعير الحصص السابقة التي سعرها صفر.
- تغيير سعر الحصة يسري على الحصص القادمة فقط، ولا يمس القديمة.

## في Supabase
1. **نسخة احتياطية أولاً.**
2. نفّذ `006_finance.sql` بعد 005 (آمن لإعادة التشغيل، بلا حذف جداول). وإن كنت نفّذت `005` سابقاً فأعد تنفيذه أيضاً ليرفع حد المرفقات إلى 20MB.
3. حد رفع الملفات على مستوى مشروع Supabase المجاني 50MB، فحد 20MB مقبول.

## قرارات افتراضية (قل لي إن أردت غيرها)
- تسجيل دفعات طلاب الأكاديمية: المدير والمشرف المالي فقط، وليس معلمهم.
- ولي الأمر لا يرى الحسابات المالية حالياً (يُقرَّر في المرحلة 10).
