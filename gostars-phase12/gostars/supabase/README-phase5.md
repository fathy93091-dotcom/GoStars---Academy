# المرحلة 5 — لوحة المعلم

## ما تحتويه
| الصفحة | المسار | الوظيفة |
|---|---|---|
| الرئيسية | `/teacher` | حصص اليوم، إحصاءات الأسبوع، أرباح الشهر، تنبيهات الباقات القريبة من الانتهاء |
| الجدول | `/teacher/schedule` | عرض «اليوم» أو «الأسبوع» (السبت→الجمعة بتوقيت القاهرة)، إضافة حصة بوقتها، إلغاؤها |
| **التقرير اليومي** | `/teacher/lessons/:id` | **هو تسجيل الحضور**: لكل طالب الحضور (حاضر/متأخر/غائب) + الواجب والدرجة + ملاحظاتك + توجيه لولي الأمر (بالذكاء الاصطناعي اختيارياً). زر واحد يحفظ كل شيء ويُتم الحصة |
| الطلاب | `/teacher/students` | قائمة طلابك مع تقدم الباقة، وإضافة طالب خاص |
| ملف الطالب | `/teacher/students/:id` | الباقة الحالية (للعرض)، تعديل تقارير الحصص، تقارير الباقة الحالية، **أرشيف الباقات المنتهية** مع ملخص ختامي بالذكاء الاصطناعي |
| أرباحي | `/teacher/earnings` | حصص الشهر: الحاضرون × السعر لكل حصة، والإجمالي |
| **باقات الطلاب** (إدارة) | `/manage/packages` | للمدير والمشرف (manage_students): إنشاء الباقة وإنهاؤها وأرشفتها |

المدير يحدد من `/manage/users` سعرين لكل معلم: **الحصة الفردية (ثابت)** و**الطالب الواحد في المجموعة**.

## كيف تعمل الباقات والأرشفة
- الباقة: **شهرية** (تاريخ بداية ونهاية) أو **بعدد حصص**.
- المستهلك = حصص الحضور (حاضر + متأخر) داخل فترة الباقة؛ الغائب لا يُحتسب.
- يُنسب كل تقرير تلقائياً إلى الباقة التي يقع تاريخ حصته ضمنها (لا يستطيع العميل تحديد `package_id`).
- تُؤرشف الباقة تلقائياً عند اكتمال عدد حصصها أو انتهاء شهرها (تُفحص عند فتح الرئيسية/الطلاب/ملف الطالب)، أو يدوياً بزر «إنهاء وأرشفة». التقارير المؤرشفة تبقى في ملف الطالب تحت «الأرشيف».
- الباقة الجديدة لا تتداخل مع السابقة، ولا يوجد أكثر من باقة نشطة للطالب.

## أجر المعلم (حسب قرارك)
- **فردي/برايفت:** سعر ثابت للحصة إن حضر الطالب (حاضر أو متأخر)، ولا أجر إن غاب.
- **مجموعة:** سعر الطالب الواحد × عدد الحاضرين (حاضر + متأخر) في التقرير اليومي؛ الغائب لا يُحتسب.
- يُثبَّت **سعر الوحدة** وقت إتمام الحصة؛ تغيير المدير للسعر لاحقاً لا يغيّر الحصص السابقة.
- الحصص الخاصة (طلاب المعلم الشخصيون) لا تُحتسب في أرباح الأكاديمية.
- الأجر لا يُقرأ من جدول الحصص مباشرة؛ يظهر عبر العروض `teacher_earnings` و`teacher_lesson_earnings` (المعلم يرى أرباحه فقط).

## الباقات: من يديرها
- **المدير والمشرف** (manage_students) فقط ينشئون الباقات وينهونها لطلاب الأكاديمية؛ المعلم يقرأ ولا يعدّل.
- استثناء منطقي: **الطالب الشخصي** لا يراه المدير أصلاً، فمعلمه المالك يدير باقته بنفسه.
- المعلم يحفظ «الملخص الختامي» للباقة فقط (عبر دالة مخصصة).

## الذكاء الاصطناعي (Gemini)
- دالة `functions/api/ai-report.js`: المفتاح في Cloudflare فقط. تقرأ بيانات الطالب **بتوكن المعلم نفسه** (فتطبَّق RLS: لا يولّد إلا لطلابه).
- لا تُرسل أرقام هواتف ولا مبالغ؛ الاسم الأول فقط. المخرجات **مسودة** يراجعها المعلم قبل الحفظ.
- حد تقريبي 30 طلباً/ساعة لكل مستخدم. حدود Gemini المجانية قد تعيد خطأ «مشغولة» فيُعاد المحاولة.
- الإرسال لولي الأمر لا يتم من لوحة المعلم؛ البوت (المرحلة 11) يرسل التقارير ذات الحالة `pending`.

## خطوات التفعيل
1. **ملفات SQL:** نفّذ `004_teacher_features.sql` بعد 001–003 (قابل لإعادة التشغيل).
2. **مفتاح Gemini:** من Google AI Studio أنشئ API key، وضعه في Cloudflare Pages → Variables and Secrets كـ **Secret** باسم `GEMINI_API_KEY`. (اختياري: `GEMINI_MODEL`، الافتراضي `gemini-2.5-flash`.)
3. تأكد من وجود `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` (تستخدمهما الدالة للتحقق بتوكن المستخدم) ثم أعد النشر.
4. اضبط أجر كل معلم من `/manage/users`.
5. باقات طلاب الأكاديمية تُنشأ من `/manage/packages`. أما إضافة الطلاب وتسجيلهم: أضفهم وسجّلهم (جدول `students` و`enrollments`) من SQL Editor الآن، فواجهة المدير الكاملة في المرحلة 8.

## ملاحظات
- التقرير اليومي يحفظ الحضور في جدول `attendance` وتقرير الطالب في `reports` ويُتم الحصة؛ لا توجد شاشة حضور منفصلة.
- الغائب يُحفظ له تقرير أيضاً (يقرر البوت لاحقاً ما يُرسل).
- الأرشفة التلقائية تعمل عند فتح اللوحة، وتُجدول لاحقاً مع البوت.
