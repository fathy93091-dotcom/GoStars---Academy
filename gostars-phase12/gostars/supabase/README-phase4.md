# المرحلة 4 — قاعدة البيانات والعلاقات

## الملفات (بالترتيب)
1. `001_auth_rbac.sql` — (المرحلة 3) profiles + permissions
2. `002_core_schema.sql` — الجداول والعلاقات والقيود والمشغّلات
3. `003_rls_policies.sql` — RLS + الصلاحيات + عرضا الأرصدة والأرباح

كلها قابلة لإعادة التشغيل ولا تحتوي أي `DROP TABLE`.

## ⚠ قبل التنفيذ: نسخة احتياطية
Supabase المجاني لا يحفظ نسخًا تلقائية. من جهازك:
```
pg_dump "postgresql://postgres:كلمة-السر@db.<المشروع>.supabase.co:5432/postgres" -F c -f backup-$(date +%F).dump
```
أو `supabase db dump -f backup.sql`. (قاعدة جديدة فارغة: يمكنك تخطيها.)

## قواعد مطبَّقة في القاعدة نفسها (لا في الواجهة)
- المعلم لا يرى أرقام أولياء الأمور ولا روابط الواتساب (للأكاديمية).
- الطالب الشخصي (`scope=personal`) لا يراه إلا معلمه المالك؛ لا المدير ولا المشرف.
- المعلم لا يغيّر سعر طالب أكاديمية، ولا يكتب `wa_status` (البوت فقط عبر service_role).
- سعر الحصة يُثبَّت وقت تسجيل الحضور (`price_at_time`) ولا يتغير بعدها.
- ولي الأمر يرى ابنه فقط، ولا يرى مدفوعات/أرصدة؛ التقييم والشهادة لا تظهر له قبل `published`.
- لا حذف للطلاب ولا للمدفوعات (تعطيل فقط). الحساب الموقوف لا يرى أي شيء فورًا.
- الزائر: النصوص الظاهرة والإعلانات «للجميع» فقط + إرسال رسالة تواصل (لا قراءة).
- الرصيد = المدفوع − المستهلك (حاضر + متأخر)، عبر `student_balances`؛ أرباح المعلم عبر `teacher_earnings`.

## قرارات أرجو تأكيدها
1. الغائب **لا** يُحتسب حصة مستهلكة. (غير ذلك؟)
2. ولي الأمر لا يرى الجانب المالي في بوابته.
3. المعلم لا يرى مدفوعات الأكاديمية، ولكنه يرى سعر الحصة المخزَّن على طلابه.
4. المشرف يحتاج صلاحية جديدة `manage_finance` للمالية (أُضيفت للواجهة).
5. دليل المعلمين لولي الأمر مؤجَّل للمرحلة 10.
